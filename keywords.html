Conditions — unless / if lines inside when blocks

Condition marks: is has becomes changes exists does near chance afford enough under. Use unless to gate on a condition (runs only while true), or if for the same line read positively. Two or more condition lines stacked one under another are one block and must all pass. otherwise (alias else) opens a block that runs when the condition line right above it was false; it sits at the same 2-space indent, and a body may hold several if/otherwise pairs. Conditions are re-checked each tick for polled events.

Data binding — bind

bind sits on its own line, outside a when. It is sugar: at parse time it becomes an ordinary when <variable> changes event whose body is set text of / set progress of, so the control follows the variable from then on.

Animation — play anim / loop anim

Animation words drive the skeleton of an AnimatedModel. No Anim Graph authoring is needed: each clip start builds a virtual graph in code, plays the clip, and swaps graphs when the clip changes.

Setup

  1. The actor needs an AnimatedModel — a skinned mesh with a skeleton, not a StaticModel.
  2. Import the animation clips into Content. Each clip is an Animation asset (for example chars/BGE Dragon 2.07/BGE Dragon 2.07 animation walk.flax).
  3. Put the EventSheet on the AnimatedModel itself, or on a parent actor above it. Both work.
  4. Name the clip in quotes: loop anim "animation walk".

What each word does

WordWhat it doesExample
play anim "<clip>"Plays once, then holds the last frame. Use for attacks, hits, one-off gestures. Fires when anim "<clip>" ends when done.play anim "dragon_fire"
loop anim "<clip>"Repeats forever until another animation word runs. Use for idle, walk and run. Never fires an ends trigger.loop anim "animation walk"
stop animStops the current clip and restores the previous clip, or the bind pose if there was none.stop anim
when anim "<clip>" endsFires once, after a play anim one-shot reaches the end of its clip. The name is matched case-insensitively.when anim "dragon_fire" ends

Clip names

  1. Folder and extension are ignored. "animation walk" finds chars/BGE Dragon 2.07/BGE Dragon 2.07 animation walk.flax.
  2. Case is ignored. "Walk", "walk" and "WALK" are the same name.
  3. A suffix works when it is unambiguous. "walk" also finds BGE Dragon 2.07 animation walk, but if two imports both contain a walk clip, use the longer "animation walk" to pick the right one.
  4. The name you pass is the name that ends. play anim "dragon_fire" pairs with when anim "dragon_fire" ends, including case differences.

Gotchas

  1. Held triggers fire every tick. loop anim on a clip that is already playing is a no-op, so when W is held + loop anim "animation walk" is safe. Do not put play anim there — a one-shot would restart every tick and never finish.
  2. One-shots hold their last frame. When the clip ends the model stays on that pose, so play a loop in the when anim … ends block to return to idle.
  3. Loops never end. when anim "animation walk" ends never fires — that trigger is only for play anim one-shots.
  4. No blending in v1. Switching clips is a hard cut; there is no cross-fade between walk and run. Keep the poses similar or accept the pop.
  5. The clip must match the skeleton. A clip from a different import or rig can play deformed. Use clips imported with the same model.
  6. stop anim is not stop moving. stop anim freezes the skeleton, not the actor's position; stop moving stops movement and leaves the animation running.

Quick example

# EventSheet on the AnimatedModel (or a parent above it) · full file: dragon.events
when me appears
  camera follows me
  loop anim "animation idle pose"

when W is held
  unless Left Shift is held
  move forward speed 40
  loop anim "animation walk"

when Left Shift is held
  W is held
  move forward speed 100
  loop anim "animation run"

when W is released
  loop anim "animation idle pose"

when Left Mouse is pressed
  play anim "dragon_fire"

when anim "dragon_fire" ends
  loop anim "animation idle pose"

Physics — Use Physics Movement

Movement is transform-based by default: move writes Position every tick, so nothing needs a collider. Tick Use Physics Movement on an actor's EventSheet and its move, goto, stop moving and push go through the actor's RigidBody instead — the physics engine then supplies collision response, CCD, and real pushing. The opt-in is per actor, not per line: one checkbox covers every movement word that sheet runs.

The one switch

  1. Select the actor's EventSheet component.
  2. Tick Use Physics Movement.
  3. The actor needs a RigidBody on itself or above it — without one the flag does nothing and movement stays transform-based.

What each word does

WordFlag off / no bodyDynamic bodyKinematic body
move <dir> speed <n>
move toward <thing> speed <n>		 Position += direction × speed × dt sets LinearVelocity = direction × speed. A move with no vertical part keeps the current vertical speed, so gravity and falling still work. swept AddMovement step — PhysX carries the body and reports contacts on the way instead of teleporting through them
stop moving cancels the ongoing move brakes horizontal velocity to 0, keeps vertical speed (a falling body keeps falling) cancels the ongoing move
push <thing> <dir> strength <n> one-tick transform nudge (strength × dt) real impulse: AddForce(direction × strength, Impulse) — Δv = strength ÷ mass one-tick transform nudge (kinematic bodies ignore forces)
goto <thing> follows the NavMesh path, writes Position follows the path via velocity and brakes on arrival follows the path via swept moves
teleport / turn / look / face unchanged in every mode — these write Position / Orientation directly, they are not physics moves

Setup contract

  1. Put the EventSheet on the RigidBody actor itself.
  2. Make the mesh and the collider(s) children of that body, at local position 0, 0, 0. The body's motion then carries the visuals. If the body is a child of the named actor, the mesh stays behind — the runtime warns once.
  3. Tick Use Physics Movement.
  4. Set the body up for its role (below).

Body recipes

RoleBodySettings that matter
Player / enemy you drivekinematicIs Kinematic on, Enable Gravity off — exact arcade speed, not shoved by other bodies
Bullet / thrown objectdynamicEnable Gravity off, Use CCD on, trigger SphereCollider; low mass so push still bites
Pushable crate / balldynamicEnable Gravity on, Override Mass on (≈1) — otherwise Flax derives ~1000 from a 1 m collider and strength 400 looks like nothing
Static target / wallnone (or a collider)leave the flag off; it never moves

Gotchas

  1. Names are exact. spawn, push and when me touches <thing> look actors up by name, case-sensitive and space-sensitive. A trailing space in the Scene panel ("Bullet ") makes all three fail — spawn logs one warning, the others fail silently.
  2. Units are centimetres — project gravity is -981, and a default cube is 100 units. Speeds like 120 are 1.2 m/s.
  3. Collider world size = Size × world scale, parent scale included. A BoxCollider with default Size 100 under a floor scaled (10, 0.5, 10) is 1000 × 50 × 1000 only if the collider's own scale is 1, 1, 1 — a local scale of (0.1, 2, 0.1) shrinks it to 100³ and everything appears to float.
  4. Gravity off floats. A dynamic body with Enable Gravity off never settles, and with gravity on but the floor collider too small it rests on invisible geometry.
  5. Dynamic bodies keep velocity. If a sheet sets move once, the body keeps sliding — pair it with stop moving (held-then-released keys), or drive it every tick with when every 0 seconds.
  6. Fast + thin tunnels. Any fast dynamic body needs Use CCD on and a trigger collider, or it passes through targets between physics steps.
  7. Contacts need colliders. Set the manager's Contact Mode to Colliders to use trigger events; the event fires on both sides, so the player's sheet sees the spike even though only the spike is a trigger. Distance mode needs no colliders at all.
  8. Templates still run. A hidden actor's EventSheet is registered at scene start, so a spawn template runs its when scene starts / when me appears blocks too. Mark it with a my IsTemplate flag and gate the live logic with unless my IsTemplate is true; clones spawned later never get the marker.
  9. Only one EventsManager per scene, on an actor that is never cloned.

How a .events file works

  1. Each when … line starts an event block. Its trigger words are classified into a trigger kind.
  2. Indented lines under it (2 spaces) are the body: unless / if conditions gate the actions, otherwise flips the condition above it; raw verb lines run in order.
  3. Actor name matching is exact & case-sensitive — TestPlayer.events attaches to an actor named TestPlayer.
  4. near is a condition, not a trigger — it must sit inside a when every N seconds block.
  5. Polled triggers (every, held, becomes, changes) run each tick; pushed triggers (pressed, clicked, hovered) fire on edges.
  6. Each event fires at most once per tick.
  7. Variables: Score = global; my health = per-actor.
  8. Hot reload: saving the file swaps the live tree without restarting.

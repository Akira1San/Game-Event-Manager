Conditions — unless / if lines inside when blocks

Condition marks: is has becomes changes exists does near chance afford enough under. Use unless to gate on a condition (runs only while true), or if for the same line read positively. Two or more condition lines stacked one under another are one block and must all pass. otherwise (alias else) opens a block that runs when the condition line right above it was false; it sits at the same 2-space indent, and a body may hold several if/otherwise pairs. Conditions are re-checked each tick for polled events.

Reuse a file — include

include sits on its own line, outside a when, like bind. It pulls another GameFiles .events file in whole, at that spot, so shared logic lives in one file: include "FPS_Controls" is the whole first-person input half (W/A/S/D, Shift sprint, Ctrl crouch, Space jump, Escape cursor lock), so a new first-person character is three setup lines and that one line, and include "Platformer_Controls" is the platformer's W walk and Space jump. An event of the sheet's own goes above the include when it has to win the same key in the same tick — the platformer's ladder grab does, so the shared unless me is climbing walk sees the climb and skips that tick.

Animation — play anim / loop anim

Animation words drive the skeleton of an AnimatedModel. No Anim Graph authoring is needed: each clip start builds a virtual graph in code, plays the clip, and swaps graphs when the clip changes.

Setup

  1. The actor needs an AnimatedModel — a skinned mesh with a skeleton, not a StaticModel.
  2. Import the animation clips into Content. Each clip is an Animation asset (for example chars/BGE Dragon 2.07/BGE Dragon 2.07 animation walk.flax).
  3. Put the EventSheet on the AnimatedModel itself, or on a parent actor above it. Both work.
  4. Name the clip in quotes: loop anim "animation walk".

  4. The name you pass is the name that ends. play anim "dragon_fire" pairs with when anim "dragon_fire" ends, including case differences.

Gotchas

  1. Held triggers fire every tick. loop anim on a clip that is already playing is a no-op, so when W is held + loop anim "animation walk" is safe. Do not put play anim there — a one-shot would restart every tick and never finish.
  2. One-shots hold their last frame. When the clip ends the model stays on that pose, so play a loop in the when anim … ends block to return to idle.
  3. Loops never end. when anim "animation walk" ends never fires — that trigger is only for play anim one-shots.
  4. No blending in v1. Switching clips is a hard cut; there is no cross-fade between walk and run. Keep the poses similar or accept the pop.
  5. The clip must match the skeleton. A clip from a different import or rig can play deformed. Use clips imported with the same model.
  6. stop anim is not stop moving. stop anim freezes the skeleton, not the actor's position; stop moving stops movement and leaves the animation running.

Physics — Use Physics Movement

Movement is transform-based by default: move writes Position every tick, so nothing needs a collider. The opt-in is per actor, not per line: one checkbox covers every movement word that sheet runs.

The one switch

  1. Select the actor's EventSheet component.
  2. Tick Use Physics Movement.

  1. Names are exact. spawn, push and when me touches <thing> look actors up by name, case-sensitive and space-sensitive. A trailing space in the Scene panel ("Bullet ") makes all three fail — spawn logs one warning, the others fail silently.
  2. Units are centimetres — project gravity is -981, and a default cube is 100 units. Speeds like 120 are 1.2 m/s.
  3. Collider world size = Size × world scale, parent scale included. A BoxCollider with default Size 100 under a floor scaled (10, 0.5, 10) is 1000 × 50 × 1000 only if the collider's own scale is 1, 1, 1 — a local scale of (0.1, 2, 0.1) shrinks it to 100³ and everything appears to float.
  4. Gravity off floats. A dynamic body with Enable Gravity off never settles, and with gravity on but the floor collider too small it rests on invisible geometry.
  5. Dynamic bodies keep velocity. If a sheet sets move once, the body keeps sliding — pair it with stop moving (held-then-released keys), or drive it every tick with when every 0 seconds.
  6. Fast + thin tunnels. Any fast dynamic body needs Use CCD on and a trigger collider, or it passes through targets between physics steps.
  7. Contacts need colliders. Set the manager's Contact Mode to Colliders to use trigger events; the event fires on both sides, so the player's sheet sees the spike even though only the spike is a trigger. Distance mode needs no colliders at all.
  8. Templates still run. An EventSheet component is attached even on an inactive actor — only the name fallback (Bullet.events auto-attach) skips inactive actors. So a spawn template with a component runs its own when scene starts / when me appears / when every blocks, while contacts, near and sight never match it (inactive actors are not contact targets). Keep live logic off the template either by gating it on the copy's marker (my spawnedFrom is "Bullet", one block per template name — clones only) or by setting my IsTemplate to true in a when scene starts block and gating with unless my IsTemplate is true (clones never see scene starts).
  9. otherwise holds until the next condition line. The lines under otherwise belong to the else branch — the gate does not close until another if/unless (or the event's next trigger pass) replaces it. So shared cleanup written after an if/otherwise pair runs only in the else case: `spawn Explosion` / `otherwise` / `spawn Gib` / `destroy me` never destroys the exploding type, because the destroy is still inside the else. Put the shared line above the branch, or re-open a gate first (`if my Health is lower than 1` then `destroy me`).
  10. Only one EventsManager per scene, on an actor that is never cloned.
  11. when every has no busy guard. A polled event re-fires on every tick its conditions hold, and a wait suspends only that one run — so an attack block that waits needs its own flag: open on my Attacking is 0, set my Attacking to 1, and put it back to 0 at the end of every branch (an otherwise branch included). Without it a 1.5 s attack starts a second telegraph on top of the first. Boss.events is the worked example.
  12. Boss fights are a schedule. Phase gates are health edges (when my Health is lower than 200), the retreat target is a named empty (goto random HidePoint — the empties share the name), and the screen bar is the ordinary progress-bar pair: show BossBar, then set progress of BossBar to my HealthPct with the percentage computed on the line above (that word takes a number, not a sum). How a .events file works

  1. Each when … line starts an event block. Its trigger words are classified into a trigger kind.
  2. Indented lines under it (2 spaces) are the body: unless / if conditions gate the actions, otherwise flips the condition above it; raw verb lines run in order.
  3. Actor name matching is exact & case-sensitive — TestPlayer.events attaches to an actor named TestPlayer.
  4. near is a condition, not a trigger — it must sit inside a when every N seconds block.
  5. Polled triggers (every, held, becomes, changes) run each tick; pushed triggers (pressed, clicked, hovered) fire on edges.
  6. Each event fires at most once per tick.
  7. Variables: Score = global; my health = per-actor.
  8. Hot reload: saving the file swaps the live tree without restarting.
